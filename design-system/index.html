How it works

The system is one CSS file, design-system/ds.css: about 6 KB, or 2 KB compressed. A small script, tools/sync-ds.mjs, copies it into every page between two comment markers. Each page therefore stays one self-contained file. It needs no extra download before it can draw, and it keeps working offline once loaded. The portfolio pages also include site.css, a 1 KB layer for headers, long text, cards and tables.

Pages adjust tokens instead of adding new colours. Signal Setup raises --tap from 42 px to 48 px for thumbs, and Classroom Signal adds its own map colours on top.

  • Colour is never the only signal: every status also has a shape and words.
  • Text is at least 4.5:1 against its background and control borders at least 3:1, in both themes.
  • System fonts only, so no font files are downloaded.
  • Sizes are in rem, so text follows the reader’s browser setting.

Colour tokens

Values and contrast ratios below are read from the live tokens, so they change when you switch the theme above.

Surfaces

  • --paperPage background
  • --panelCards, lists and inputs
  • --accent-softSelected rows and choices
  • --hoverHover on rows and buttons
  • --danger-softError notice background

Text

  • --inkBody text and headings
  • --ink-2Secondary text
  • --ink-3Muted text; the lightest text allowed
  • --accentLinks, focus, selection, primary buttons
  • --on-accentText on primary buttons
  • --dangerError messages and invalid fields

Lines

  • --rule-strongBorders of buttons, fields and chips
  • --ruleDividers between rows and sections

Status

The same four hues in both themes. A status mark is readable if either its fill or its outline (--mark-stroke) reaches 3:1 against the panel.

  • --goodMeets target
  • --warnBelow target
  • --critOffline
  • --noneNo data (drawn as a ring)
  • --mark-strokeOutline of status marks

Type scale

Seven sizes, all in rem. Dense data screens use 15 px body text; reading and touch-first screens use 17 px.

--text-hero25–40 px, grows with the screen

27 of 128 schools reach 20 Mbps

--text-xl36 px · one key number

39 Mbps

--text-lg21 px · page and panel titles

Mese Primary School

--text-md17 px · reading and touch-first text

The box checks your school’s internet every day, by itself.

--text-base15 px · dense data screens

30 schools are offline and 15 have no speed test yet.

--text-sm13 px · labels, hints, captions

Each large square is 5 km.

--text-xs12 px · chart labels only

9 Oct · 14 Oct · 22 Oct

Interface text uses --font-ui (the device’s own sans-serif). Place names use --font-place, an italic serif, like the labels on a printed map: Tobani, Wuraka.

Buttons

One primary action per screen. Every button is at least --tap tall: 42 px by default and 48 px on touch-first pages.

Chips

A chip is a filter you switch on and off. The off state is dashed, dimmed and announced as “not pressed”, so it is never shown by colour alone. Try them.

Markup
<button type="button" class="chip" aria-pressed="true">
  <svg …status mark…></svg><span>Meets target</span><b>27</b>
</button>

Form fields

Every field has a visible label. Help text and errors sit under the label and are linked to the field with aria-describedby. An error says how to fix the problem, not only that something is wrong.

For example: 0712 345 678
6 letters and numbers, on the sticker under the box.

Codes never use O, 0, I or 1. Look at the sticker again.

Does your school have electricity?
Markup
<div class="field">
  <label for="code">Box code</label>
  <span class="help" id="code-help">6 letters and numbers…</span>
  <input id="code" type="text" aria-invalid="true"
         aria-describedby="code-help code-err">
  <p class="error" id="code-err">…</p>
</div>
<label class="choice"><input type="radio" name="power"><span>No electricity</span></label>

Notices

A notice uses the left border colour and an icon or status shape, and its first words say what kind of message it is.

Saved on this phone. It will be sent when the phone has signal again.

Sent. The district office has your answers.

Please do not set up this box. It was sent to a different school.

Not sent. Check your connection and try again.

Focus

Keyboard focus is a 3 px --accent outline with a 2 px gap, on every control, from one rule: :focus-visible{outline:var(--focus);outline-offset:2px}. It appears for keyboard users and not on mouse clicks. Press Tab to move through this page, or compare with the example below.

Focused button Focused chip Focused link

Pages that move focus themselves, for example to a new screen’s heading, put it on an element with tabindex="-1". They also make sure nothing fixed, such as a sticky button bar, covers the focused element (WCAG 2.4.11).

Rules for using it

Do

  • Pair every status colour with its shape and its words.
  • Use --ink-3 as the lightest text colour.
  • Add a token when a page needs a new colour, and check its contrast in both themes.
  • Keep every control at least --tap tall.
  • Edit ds.css, then run node tools/sync-ds.mjs.

Don’t

  • Use colour as the only difference between two things.
  • Use --rule or a status colour for text.
  • Write hex values inside components.
  • Shrink touch targets to fit more on a row.
  • Edit the copied block inside a page: the next sync replaces it.
